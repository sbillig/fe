A const argument of a trait reference, such as `T: Has<{ 1 / 0 }>` or `impl Has<{ runtime() }> for u8`, is now reported when it fails compile-time evaluation or calls a non-const function, including a fault that only applying a default reveals (`T: Has<0>` where the default is `[u8; { 1 / N }]`). Previously the whole bound was dropped silently, so the program checked cleanly and the bound was never enforced. An integer fault in a const argument now points at the faulting operation rather than at the whole block.
