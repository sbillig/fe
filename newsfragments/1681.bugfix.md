The borrow checker no longer accepts calls that let a function write or read through an alias of a borrow it holds. For example, a function that takes `value: mut u256` and a raw pointer to a stored reborrow of the same memory could write through the pointer while `value` was live. A function now records the separation it could not prove, and each caller must establish it from the places it actually passes or leave it to its own callers. A borrow stored in contract storage is treated as invalid, so a method on a storage struct that contains a borrow-typed field must reassign that field before using it.
