A tuple-variant or record pattern whose name doesn't resolve is now an error. `Bar(y) => ..` with no `Bar` in scope was accepted and then crashed the backend, and `Foo { a } => ..` was accepted whenever the matched value's type was a struct named `Foo`, even with that struct out of scope. A pattern naming an ambiguous variant, such as `Some(x)` with both a glob-imported and the prelude's `Some`, reports the ambiguity, and the field bindings of an unresolved record pattern no longer also report themselves as undefined.
